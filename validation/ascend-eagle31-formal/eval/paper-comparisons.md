The EAGLE-3 paper reports a maximum 6.5× speedup in its wider study. Its production-serving tables above are the closer comparison for SGLang output throughput. PR #575 trains a parallel Qwen3-8B drafter for 110k steps and uses k=5 for its P-EAGLE demo, k=3 for the external EAGLE3 baseline and k=15 for DFlash. The baseline row in its chart is EAGLE3 at 1.00×. Its concurrency sweep covers 1, 2, 4, 8, 16, 32 and 64. P-EAGLE peaks at 1.22× at C32 and reaches 0.98× at C64. Its C1 EAGLE3 row reports AL 2.30, 43.3% acceptance, TPOT 1.91 ms and TTFT 15.7 ms. Its C1 P-EAGLE row reports AL 2.75, 35.0%, 1.64 ms and 23.4 ms. These columns are a useful reporting format for the 910B3 runs. The absolute times, acceptance denominators and published speedups are conditional on each source's method, workload and serving hardware. On 910B3, report separate ratios at identical concurrency, input and output cap. The deployment ratio is candidate end-to-end output tok/s divided by the same SGLang target-only service's end-to-end output tok/s. An additional reference ratio uses the published, same-target Nex EAGLE3 throughput as denominator. Both numbers include prefill, scheduling, decode and local HTTP delivery. In the MT-Bench SSE companion, TTFT is time from dispatch until first SSE event whose cumulative completion count becomes positive. Conventional request TPOT is (last token event time − first token event time) / (emitted tokens − 1). Responses without two distinct token events have undefined TPOT and their count is reported. The additional per-request decode throughput removes all tokens from the first chunk from its numerator and sums observed post-first-chunk intervals in its denominator. At C4 these overlap in wall time, so this is a per-request decode statistic. The standalone production ratio uses the non-streaming, measured wall interval.

A checkpoint demonstrates deployment throughput improvement at a specified budget and C only if the observed candidate/AR ratio exceeds 1. Show both replicate observations, task score and bit-exact request parity. If outputs differ, keep the raw ratio and leave the equal-output speedup unset. Compare the magnitude against the appropriate source metric; reaching a numerical ratio with a different target and hardware does not reproduce that paper's experiment.
